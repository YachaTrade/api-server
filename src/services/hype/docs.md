## HypeService 개요

HypeService 는 하이프 포인트, 투표, 보상 데이터를 제공하는 서비스 계층이다. 대부분의 조회는 Redis 캐시를 우선 확인하고, 조회 결과를 다시 캐시에 저장해 부하를 줄인다.

### 주요 기능
- **토큰 정보(`get_hype_token`)**: 최신 혹은 특정 에폭의 하이프 토큰 정보를 조회한다. 에폭별로 캐시 키를 분리해 저장한다.
- **포인트/에폭 조회**: 계정 하이프 포인트(`get_hype_point`), 현재 에폭(`get_hype_epoch`)을 조회하고 캐시한다. 자정(UTC)에는 에폭 캐시를 강제로 무효화한다.
- **이력 조회**: 투표, 포인트, 보상, 보상 추가 이력을 페이지네이션과 함께 제공하며, 결과를 Redis 에 캐시한다.
- **투표 처리(`vote`)**: 컨트롤러에 위임해 투표 레코드를 생성하고 발생한 오류를 `InternalError`로 래핑한다.
- **재무 데이터**: 커뮤니티 금고 잔액, 총 사용 포인트를 조회하고 캐시한다.

### 에러 및 로깅
- 캐시 쓰기 실패 시 서비스 동작은 유지하고 `error!` 로그를 남긴다.
- 컨트롤러 호출 실패는 `AppError::InternalError`로 변환하여 상위 계층에 전달한다.

### 의존성
- `PostgresDatabase`, `RedisDatabase`
- `HypeController`: 모든 실제 쿼리 수행
- `PaginationParams`: 목록 API 의 페이지네이션 파라미터
